# Python stream processing is NOT Apache Flink

The original standalone `data-engineering/flink/stream_processor.py` contained an asynchronous **Python** Kafka consumer plus application-level state/alert windows. It did not import Flink, run a Flink cluster, use Flink SQL, establish distributed watermarks, have Flink checkpoints or provide exactly-once streaming guarantees. To prevent misleading readers, the exact source was moved to [stream_processor.py](stream_processor.py) and the misleading active source file removed. There is no automatic change in behavior or claimed performance. The module is an illustrative optional example and **not** part of the independently verified fleet dispatch / GPS golden path.

True Apache Flink acceptance would require a Flink runtime job, real Kafka input, event-time/watermark assertions, checkpoint/restart and failure/replay tests on a disposable cluster. This is an open architecture decision, not a requirement to claim Flink for this small product. The simpler PostgreSQL/PostGIS + Kafka + Airflow/dbt approach remains the evidence-backed option. The hygiene gate checks the path move at every pull request.
