# P1 unified same-event browser → Kafka → PostGIS → Parquet → dbt

The [unified CI](../../.github/workflows/p1-unified-gps-dbt.yml) runs the existing real authenticated GPS Playwright test on a *single disposable GitHub runner* with a PostGIS `fleetflow_test` DB and a real local Redpanda broker. The browser test logs in, submits a synthetic GPS event to FastAPI, verifies the queued transactional outbox → Kafka ACK → consumer PostGIS write → authenticated WebSocket journey. After the browser terminates, the new exporter independently reads **that exact event UUID** from its source outbox row, requires published broker status and corroborating last-accepted PostGIS vehicle event ID; it refuses remote/non-test DBs and mismatched event identities. The **same** serialized event becomes the immutable JSONL input for the original Parquet replay pipeline, passes full reconciliation, loads transactionally and idempotently into that same DB twice, and is transformed using the actual dbt PostgreSQL facts. An independent SQL/Parquet assertion requires the *same* event and vehicle ID, one accepted fact, zero duplicates, and one resulting vehicle-hour row. Artifacts include hashed source receipt, Parquet manifest and dbt run results.

This is a reproducible **single-source fixture golden path**, stronger than two independently passing test suites. It is not a live customer, commercial fleet SLA, travel-network distance, a production Kafka-to-S3 sink or continuous dbt orchestration; a manual post-browser export connects broker-tested durable data to batch Parquet analytics. Explicit approval remains required for production merges, GPS privacy/retention, public API hosting and AWS spend.
